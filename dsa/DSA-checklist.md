# 27. How to Practice Each Problem

For every problem, use this process:

1. **Understand the problem**
2. **Identify the pattern**
3. **Think for 15–30 minutes**
4. **Write the solution yourself**
5. **Test edge cases**
6. **Analyze time complexity**
7. **Analyze space complexity**
8. **If stuck, study the solution**
9. **Close the solution**
10. **Implement it again from memory**
11. **Revisit after a few days**

Do not simply collect solved problems.

The important metric is:

> **Can I recognize the underlying pattern when the problem is presented differently?**

# 29. Completion Metric

Do **not** aim for "I solved 500 LeetCode problems."

Instead aim for:

- [ ] I can recognize common DSA patterns.
- [ ] I can implement the common templates without help.
- [ ] I can explain the time and space complexity.
- [ ] I can solve most Easy problems independently.
- [ ] I can solve a reasonable portion of Medium problems independently.
- [ ] I can make meaningful progress on Hard problems.
- [ ] I can debug my own implementation.
- [ ] I can explain why my solution works.

**Once these are true, stop expanding the DSA syllabus and move your effort to projects, Java/Spring, databases, system design, and interview-specific practice.**

---

# Final Principle

This is a **finite checklist**, not a requirement to solve every possible DSA problem.

For interview preparation, prioritize **patterns and depth over problem count**.

A good target is roughly **150–220 carefully selected problems**, with repeated practice of the underlying patterns.
